# Quick Task 260802-005 — category-set filters and a deeper pool

Wrap-up before the final test. Two changes, one measurement run.

## T1 — Retrieval accepts a category set

`dense_search` / `sparse_search` / `fuse` / `retrieve*` take `str | list[str] |
None`. Qdrant switches from `MatchValue` to `MatchAny`; the sparse post-filter
tests membership. A single string keeps behaving exactly as it does now.

## T2 — Family expansion

260802-004 measured the filter as `+7/-6` against no filter (a coin flip) while
a gold filter is `+9/-0`; 260802-003 showed 16 of the 23 remaining wrong tags
are *within* an insurance family (property = apartment/mortgage/business;
personal-risk = life/personal-accident/loss-of-working-ability/
diseases-disabilities/long-term-care). A set-valued filter is how that gap
closes. `rag/classify.py` gains the family map, and the agent builds its filter
under `harness.category_filter`:

| policy | filter for a sub-question tagged `[mortgage]` |
|---|---|
| `single` (today) | `mortgage`, and nothing when 2+ tags |
| `set` | the tags themselves, however many |
| `family` | `{apartment, business, mortgage}` |
| `none` | no filter ever |

Default stays `single` until the run says otherwise; the winner is committed
after the measurement, not before it.

## T3 — Pool depth K=100

`dense_top_k`/`sparse_top_k` 20 → 100 in `configs/default.yaml`. 260802-004
found depth alone delivers +3 of 84 groups because the 0.35 gate discards what
the deeper pool reaches; the open question this run answers is whether a
family-filtered pool changes that. Rerank cost goes 20 → 100 pairs per query
(~0.9 s on the L40S).

## T4 — Re-measure on the validation half

`retrieval_audit` gains `predicted-set`, `predicted-family` and `gold-family`
modes, all replayed from 260802-003's predictions.jsonl — no classification
calls. One arm (`pdf-per_table`, production), K=100, 6 filter modes, validation
half only; the holdout stays unspent for the final test.

## T5 — Wrap

Set `harness.category_filter` to the winner, analysis note, STATE row, push.
Deliberately out of scope: `top_n`/gate re-tuning, which needs a scored
generation run (260802-004's follow-up 1) — this task reports what the same
data says about it and stops there.

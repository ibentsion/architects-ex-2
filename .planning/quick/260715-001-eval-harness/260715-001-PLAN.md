# Quick Task 260715-001: Evaluation harness for Exercise 2 (Harel support agent)

**Created:** 2026-07-15
**Mode:** quick (lightweight tracking — GSD agent pipeline unavailable in this repo)

## Goal

Build an LLM-as-judge evaluation harness that scores answer batches
(`baseline_answers.jsonl` format) against the dev set
(`reference_questions.json`), producing numeric per-category grades and a
markdown report with per-domain / per-difficulty / per-source-count analysis
plus prioritized improvement suggestions. Run it on the baseline answers.

## Locked decisions (from user)

- Default judge: `deepseek-ai/DeepSeek-V4-Pro` via `tf_client.chat` (pinned, temperature 0).
- Committee support: configurable list of judge models; default is a single judge.
  Aggregation: median for numeric scores, majority for categorical verdicts,
  disagreement flagged in output and report.
- Questions/answers are Hebrew; judge output, metrics, and report are English.

## Design decisions (Claude's discretion)

- Package `evalharness/` with CLI `python -m evalharness.run`.
- Judge categories (0–10 numeric): correctness, completeness, conversational_quality.
  Categorical: verdict (correct / partially_correct / incorrect / refusal),
  hallucination (bool — confident claim contradicting ground truth; refusal is
  never a hallucination).
- Multiple judge prompt variants selectable via `--prompt`: `rubric` (default,
  anchored scales), `strict` (terse fact-agreement), `claims` (decompose ground
  truth into atomic facts, count supported/contradicted).
- Citation accuracy is deterministic (no LLM): per-question recall over
  `any_of` source groups (group satisfied if any cited file+page matches any
  member) and precision over cited items.
- Outputs per run directory: `judgments.jsonl` (per-question, raw + aggregated),
  `metrics.json` (programmatic aggregates), `report.md` (analysis + suggestions).
- Concurrency via ThreadPoolExecutor (default 8 workers); JSON output enforced
  by prompt + parse-with-retry.

## Tasks

1. Implement `evalharness/` package (prompts, judge, citations, metrics, report, run).
2. Offline smoke test (citations + aggregation + report with mocked judgments).
3. Live run on `baseline_answers.jsonl` (needs NEBIUS_API_KEY); commit results
   under `eval_results/baseline/`.

## Verification

- `python -m evalharness.run --questions reference_questions.json --answers
  baseline_answers.jsonl --out eval_results/baseline` completes on all 48
  questions and writes the three artifacts.
- Report contains per-domain, per-difficulty, and per-source-group-count tables
  and at least three prioritized improvement suggestions.

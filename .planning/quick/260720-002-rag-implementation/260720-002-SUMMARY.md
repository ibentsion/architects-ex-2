## What's NOT done — full corpus ingestion

The 12-category, ~571-file corpus was **not fully ingested** in this session. A
background ingest ran ~59 minutes, parsed 82/283 remaining PDFs (business category
was ~91% done when stopped), and was intentionally killed rather than let run past a
~3-hour budget — full ingest is projected at 5+ hours (parse + Stanza normalize +
embed, sequentially, on this CPU). The ingestion CLI's atomic `.tmp-<pid>` swap meant
the kill left `rag_index/default/` untouched (still the working 2-category index).
**Caches are warm**: `cache/parsed/`, `cache/tokens/`, `cache/embeddings/` retain all
work done so far (grew 26M→46M), so a resumed run skips everything already processed
— this is exactly the incremental-caching design added to the plan in this task's
first half.

Consequently the 48-question dev-set eval reported above is **partial**: 36/48
questions target domains outside apartment/travel and correctly hit the fallback path
(0 hallucination, but scored as non-answers by the judge), which is why the
*aggregate* eval numbers look worse than baseline even though the *per-ingested-domain*
numbers are strictly better. See `eval_results/rag-default/report.md` for the full
breakdown.

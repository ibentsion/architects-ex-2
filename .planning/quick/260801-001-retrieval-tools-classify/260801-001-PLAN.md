# Quick Task 260801-001 — Retrieval stage tools + query classification/routing

Two deliverables (user request, decisions confirmed via AskUserQuestion):

1. Expose the RAG retrieval components (dense search, sparse search, RRF
   fusion, reranking) as **parameterized tools without generation**, callable
   by an external harness **through the query CLI**, with CLI flags for the
   retrieval/filtering parameters. Defaults must remain exactly as in the
   current code (config-driven).
2. **Query category classification**: given a free-form query, predict
   single- vs multi-category, which of the 12 corpus categories apply, and
   split the query into separately-answerable sub-questions. Exposed both as
   a standalone `classify` tool AND wired into the answer flow behind an
   opt-in `--route` flag (auto: classify → per-sub-question retrieval with
   category filters → one composed answer).

## Decisions (confirmed with user)

1. **Tool shape** — stage subcommands: `dense`, `sparse`, `fuse`
   (dense+sparse+RRF), `rerank`, `retrieve` (full pipeline), `classify`.
2. **Location** — extend `rag.cli.query` (dispatch on first positional arg;
   legacy invocations `python -m rag.cli.query --config X "שאלה"` unchanged).
3. **Classifier** — LLM via `tf_client.chat`, default model =
   `config.generation.model`, `--model` override; strict-JSON prompt listing
   the 12 categories with Hebrew descriptions; unknown categories dropped;
   parse failure degrades to single-mode/no-filter (never blocks answering).
4. **Integration** — standalone `classify` subcommand AND `--route` on the
   answer flow. Routed answers: retrieve per sub-question (category filter
   only when a sub-question maps to exactly one category), pool + dedupe
   gated chunks by chunk_id (keep max rerank score, sort desc), then ONE
   generation call with the original question over the pooled context.
   `--route` is mutually exclusive with an explicit `--category`.

## Tasks

### T1 — Retriever per-stage public API with per-call overrides
Files: `rag/retrieve/retriever.py`, `tests/test_retrieve.py`
- Public methods with per-call overrides falling back to instance defaults:
  `dense_search(q, *, top_k=None, category=None)`,
  `sparse_search(q, *, top_k=None, category=None)`,
  `fuse(q, *, dense_top_k=None, sparse_top_k=None, rrf_k=None,
  category=None)` → hydrated `RetrievedChunk`s with dense/sparse/rrf scores,
  `rerank_candidates(q, candidates, *, gate_threshold=None, top_n=None)`.
- `retrieve()` becomes the composition of `fuse` + `rerank_candidates` and
  keeps `last_stats` behavior identical. Old `_dense_search`/`_sparse_search`
  callers (smoke test) updated — replace, don't deprecate.
- Verify: existing + new unit tests pass (`pytest tests/test_retrieve.py`).

### T2 — Stage subcommands on the query CLI
Files: `rag/cli/query.py`, `tests/test_query_cli.py` (new)
- Dispatch: if first CLI positional ∈ {dense, sparse, fuse, rerank, retrieve,
  classify} → tools subparser; else legacy parser (behavior unchanged).
- All tool commands: `--config` required, JSON to stdout, human noise to
  stderr. Flags (defaults = config values): `dense`/`sparse`: `--top-k`,
  `--category`; `fuse`: `--dense-top-k --sparse-top-k --rrf-k --category`;
  `retrieve`: fuse flags + `--gate-threshold --top-n`; `rerank`:
  `--candidates FILE|-` (JSON list of chunk_ids or objects with `chunk_id`;
  texts hydrated from the dense payload store) + `--gate-threshold --top-n`.
- `retrieve` output includes per-stage `retrieval_stats`.
- Verify: CLI tests with faked `load_retriever` (parse → plumbing → JSON).

### T3 — Query classifier + routed answering
Files: `rag/classify.py` (new), `rag/types.py`, `rag/cli/query.py`,
`tests/test_classify.py` (new)
- `rag/classify.py`: `CATEGORIES` (12 dirs + Hebrew descriptions),
  `QueryClassifier(model, ...).classify(question) -> Classification`
  (strict-JSON prompt, code-fence stripping, category validation, graceful
  fallback). `Classification`/`SubQuestion` pydantic models in `rag/types.py`;
  `Answer` gains `classification: Classification | None` and
  `classification_ms: float | None`.
- `QueryEngine`: `--route` support in single/interactive/batch modes —
  classify, retrieve per sub-question, pool/dedupe, single generation with
  the original question; classifier cost added to `cost_estimate`;
  `retrieval_stats` = per-stage element-wise sum over sub-question retrievals
  (documented approximation). Gate-fail on an empty pool keeps the existing
  zero-LLM fallback path.
- `classify` subcommand: loads config only (no index/retriever), prints the
  `Classification` JSON.
- Verify: classifier tests with mocked `chat`; routing tests with faked
  retriever/generator/classifier; full `pytest` (non-slow) green.

## Out of scope

- No changes to ingest, eval harness, or existing configs.
- No new config block for the classifier (model defaults to
  `generation.model`; CLI `--model` covers experimentation).

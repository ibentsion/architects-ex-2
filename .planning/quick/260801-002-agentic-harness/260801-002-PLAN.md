# Quick Task 260801-002 — Agentic answer harness

An agent engine on top of the classify/retrieve tools (260801-001) that
handles single query-answer, multi-part queries, dependent multi-hop
reasoning, and tool-based calculation — surfaced through the existing query
CLI (single/interactive/batch modes reused, not duplicated).

## Decisions (confirmed with user)

1. **Architecture: hybrid fast-path.** Classify first (one quick call).
   Single-topic, no-calculation queries take the direct retrieve→generate
   path; independent multi-part queries take concurrent retrieval → pooled
   generation; only calculation / dependent-reasoning queries enter an
   agentic tool-calling loop (tools: `retrieve`, `calculate`; capped hops).
2. **`--route` is replaced** by the harness (its non-loop paths subsume it).
   Query CLI gets `--engine {rag,agent}` instead (default `rag`, current
   behavior).
3. **Model roles:** new `harness:` config block. Orchestration (classifier +
   agent loop + expression writing) = `openai/gpt-oss-120b` with
   `reasoning_effort: low` (fast tool calling — LIVE-VERIFIED: TF returns
   native OpenAI `tool_calls` for gpt-oss-120b). Final answer synthesis =
   `generation.model` (DeepSeek-V4-Pro today) via the existing Generator
   (grounded_cite prompt + citation validation).
4. **Calculation is a tool, never LLM arithmetic**: AST-whitelist expression
   evaluator; the orchestrator LLM only WRITES the expression.

## Concurrency design (user asked serial-vs-concurrent explicitly)

Concurrent: per-sub-question retrievals (ThreadPoolExecutor; embedding is
HTTP-bound); multiple tool calls issued in one orchestrator turn. Sparse
stage (stanza normalizer + bm25s) guarded by an internal lock — stanza
pipelines are not thread-safe; dense (qdrant-local reads) and CrossEncoder
inference are safe for concurrent reads.
Serial: classification (everything routes on it) → retrieval; agent hops
(hop N+1 consumes hop N results); calculation (after its inputs are
retrieved); final synthesis (after all evidence).

## Tasks

### T1 — Foundations: harness config, calculator, classifier flags
Files: `rag/config.py`, `configs/default.yaml`, `rag/agent/{__init__,calculator}.py`,
`rag/classify.py`, `rag/types.py`, `tests/test_agent.py` (new), `tests/test_classify.py`
- `HarnessConfig` (required block, defaults in default.yaml like every other
  block): `orchestrator_model`, `orchestrator_max_tokens`,
  `orchestrator_extra_params` (reasoning_effort low + allowed_openai_params),
  `max_hops` (default 4), `max_workers` (default 4).
- `rag/agent/calculator.py`: `calculate(expression) -> float` — AST
  whitelist (numbers, + - * / // % **, unary ±, parentheses, round/abs/min/max),
  length + exponent caps, clear errors. No eval.
- Classifier: prompt + parse gain `needs_calculation` and `dependent`
  booleans (fields on `Classification`, default False; fallback keeps them
  False). Classifier default model moves to `harness.orchestrator_model`.

### T2 — tf_client tool-calls, retriever thread-safety, AgentEngine
Files: `tf_client.py`, `rag/retrieve/retriever.py`, `rag/agent/engine.py`,
`rag/types.py`, `tests/test_agent.py`
- `tf_client.chat(..., return_message=True)` → (message, usage, cost)
  surfacing `tool_calls`; existing callers unchanged.
- `Retriever`: `retrieve_with_stats()` core returning (results, stats) with
  no shared-state mutation + internal sparse-stage lock; `retrieve()` wraps
  it and sets `last_stats` (serial convenience only).
- `rag/agent/engine.py`: `AgentEngine(config)` with the QueryEngine answer
  contract (`answer`, `_answer` -> (Answer, tokens), `close`):
  - classify → fast path A (single, direct) / fast path B (independent
    multi, `retrieve_many` concurrent + pool/dedupe) / agent loop
    (prefetch concurrent retrievals, then native-tool-calling loop with
    `retrieve` + `calculate`, parallel tool calls executed concurrently,
    `max_hops` cap) → synthesis via Generator over pooled evidence, with a
    calculation-results block appended to the question.
  - Orchestrator/loop failure degrades to fast path B (never blocks).
  - `Answer.trace`: list of hop/tool-call records (tool, args, ms, summary)
    for eval/debugging; classification + costs accounted as in --route.

### T3 — CLI integration, cleanup, tests, live E2E
Files: `rag/cli/query.py`, `tests/test_query_cli.py`, `tests/test_classify.py`
- `--engine {rag,agent}` (default rag) picks QueryEngine vs AgentEngine;
  single/interactive/batch modes reused as-is (engine-agnostic already).
- Remove `--route`, `QueryEngine.route`, `_answer_routed` (replaced by the
  agent engine; routed tests migrate to AgentEngine fast path B).
- `classify` subcommand default model = orchestrator model.
- Full non-slow suite green; live E2E: simple query, two-topic query, and a
  calculation query through `--engine agent`.

## Out of scope

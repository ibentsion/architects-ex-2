# Summary — reference dataset v2

`reference_questions_v2.json`: **108 verified questions across all 12
categories**, each written by one of three models from a real corpus page and
admitted only after gates run by the other two.

## What was built

| File | Role |
|------|------|
| `refgen/schema.py` | The spec as code: per-kind invariants (an unanswerable item cites nothing; a multi-source item is hard and cites two different files) and collection invariants (all 12 categories, per-cell counts, distinct pages per cell, no leakage from held-out v1) |
| `refgen/inventory.py` | Page inventory, coverage-driven sampler, multi-source pairing, per-category BM25. Drops scrambled pages and scraped-site boilerplate |
| `refgen/prompts.py` | Generation prompts per kind/difficulty (v1 items as form anchors, always from another category) + form/difficulty/topicality gate prompts |
| `refgen/verify.py` | The gates, run concurrently on models that did not write the item |
| `refgen/generate.py` | Item builder: draw → generate → gate → accept, or retry with the reason |
| `refgen/run.py` | CLI, 12 categories in parallel, per-item checkpointing |
| `refgen/audit.py` | Re-check any dataset against the spec; `--gates` re-runs the LLM gates with a reshuffled verifier assignment |
| `tests/test_refgen.py` | 43 tests, LLM mocked — mostly that each gate *can* reject |
| `evalharness/*` | `answerable: false` scoring (abstention), `by_kind` slice |

## How the tasks were formalized

Each kind is a spec with a machine-checkable acceptance test. The derivability
gate is the citation judge from 260731-001 — so an item is admitted under the
same rule the harness later scores systems by.

| kind | accepted iff |
|------|--------------|
| `standard` | the citation judge rules its source page establishes its answer `fully` |
| `multi_source` | both pages together rule `fully` **and** each page alone does not (leave-one-out — this is what "spans two citations" means operationally) |
| `unanswerable` | a BM25 sweep of the whole category, judged, rules `not_at_all`, and a topicality check confirms a real customer of that category would ask it |

Plus, for every item: an independent model must agree with the difficulty
label, the form gate must accept it as a customer's question, sources must
resolve through `PageStore`, and it must not duplicate an existing question.
Generators round-robin; no model ever verifies its own item.

## Decisions

1. **132 target** — 108 standard (3 per category×difficulty) + 12 unanswerable + 12 multi-source.
2. **v1 is held out**, not merged: no v2 item cites a page v1 quizzes on, none paraphrases a v1 question.
3. **Classify and place** — difficulty is the independent judge's verdict, not the generator's claim. Forcing the requested label made the two fight; the item is now filed under the difficulty it earns.
4. **Models: gemma-3-27b-it, Qwen3-235B-A22B-Instruct, Nemotron-3-Ultra-550b.** GLM-5.1 was dropped after taking 537 s on one real generation prompt (gemma 5.8 s, Qwen 12.5 s, Nemotron 25 s). gpt-oss-120b is faster still but generates the RAG system's answers and judges them, so it is kept out of question authorship.
5. **Harness extended** for `answerable: false`: refusal is correct, answering anyway is a hallucination, citation accuracy excluded.

generators:  gemma 34 / Qwen 33 / Nemotron 41

24 short of target: 13 hard + 4 medium standard slots, 6 multi-source, 1

filtering. Shortfalls are reported, never padded with unverified items.

## What the trials found (all fixed)

The first trial accepted 3 of 11 items in 30 minutes and then lost them to a
timeout. Every cause was ours, not the corpus:

- **Gates ran sequentially** (~10 min/item) → now concurrent, ~90 s.
- **No checkpointing** → a killed run discarded everything paid for; now every accepted item is appended to `.partial.jsonl` immediately. This later saved 104 items from a crash.
- **The form gate rejected answers for naming a claim form or procedure code**, confusing that with pointing at the source document.
- **The generators wrote "הדף אינו מציין..." as ground truths** instead of skipping thin pages; now forbidden and detected in code.
- **Scraped `.txt` pages are mostly site chrome** — the median dental page was 80% navigation, which cleared the length filter on its own. Now stripped.
- **"Hard" was taught wrong.** The rule said "arithmetic over numbers on the page", so generators hunted for a page containing a worked example and, failing, wrote single-fact questions. Every single-source hard item in v1 uses one shape: *the customer supplies a figure, the page supplies the rate*. Teaching that shape took difficulty rejections to zero.
- **"Multi-source" was taught wrong** in the same way — 12 of 12 failed. v1's items ask about two things at once, one per page. Teaching that shape, and spending the budget on more pairs rather than more retries, produced 6.
- **pdfium is not thread-safe** and segfaulted the 12-way run twice — once from concurrent use, then again via weakref finalizers running teardown on other threads. Inventories are now built serially in the main thread.
- **A schema violation killed the whole run** (a non-Hebrew question passed the form gate, and the validator raised out of a worker). Now an ordinary rejection.

## Known limitations

- Unanswerability is proven against a BM25 sweep of the category with plain
  Hebrew tokenization, not a corpus-wide impossibility proof. Recorded per item.
- Residual Docling word-order scrambling survives on some pages; those pages are
  excluded from the question pool rather than trusted.
- Thin categories (dental especially) cannot fill their hard cells.

## Verification

- `pytest -m "not slow and not llm"` — 309 passed.
- `python -m refgen.audit reference_questions_v2.json` — every item conforms;
  the 18 reported problems are all count shortfalls, no invalid items.

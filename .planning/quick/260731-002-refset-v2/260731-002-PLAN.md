# Quick Task 260731-002 — reference dataset v2

Build `reference_questions_v2.json`: 132 questions covering all 12 categories,
each generated by one of three models from real corpus pages and accepted only
after passing machine-checkable gates.

## What v1 looks like (the form being reproduced)

48 questions, 8/12 categories, 2 per (category, difficulty).

- **Form** — first-person customer voice with a concrete situation
  ("קרה נזק בדירה שלי לפני חודש..."), never "what does section 5 say".
  Self-contained; answerable without seeing the document.
- **Ground truth** — short and decisive, usually opens כן/לא, carries the exact
  number/limit/condition (46–266 chars).
- **Difficulty is structural, not lexical:**
  - `easy` — one fact, one page, direct restatement.
  - `medium` — a specific limit/condition buried in a document, or correcting a
    customer misconception. One source.
  - `hard` — two sources synthesized (10/48 have 2 source groups), or
    arithmetic over retrieved numbers (2% × 1,200,000 = 24,000 ₪; the
    5% + 0.3%/day premium refund).
- **Schema** — `{id, domain, difficulty, question, ground_truth_answer,
  ground_truth_sources: [{any_of: [{file, page}]}]}`.

## Decisions

| # | Decision | Source |
|---|----------|--------|
| 1 | **132 items** — 108 standard (3 per category×difficulty) + 12 unanswerable + 12 multi-source (one each per category) | user |
| 2 | **All 108 standard items are generated fresh.** v1 is held out as the validation/test set and is never merged into v2 | user |
| 3 | The eval harness learns `answerable: false`: refusal = correct, a confident answer = hallucination, citation accuracy excluded | user |
| 4 | New file `reference_questions_v2.json`; the exercise-provided v1 file is untouched | user |
| 5 | `multi_source` items are always `hard` — v1 defines multi-document as what makes a question hard | assumption |
| 6 | `unanswerable` items rotate across difficulties (4 easy / 4 medium / 4 hard). Difficulty here = temptation: easy is plainly outside the corpus, hard is a gap next to a fact the corpus *does* state | assumption |
| 7 | v1 is a **held-out** set, so v2 must not leak into it: no v2 item may use a (file, page) that any v1 item cites, nor be a near-duplicate of a v1 question | leakage guard |

Per category: 3 easy + 3 medium + 3 hard + 1 multi-source (hard) + 1
unanswerable = 11. Twelve categories = 132.

## Formalizing the generation tasks

Each **kind** is a spec whose acceptance criteria are machine-checkable. The
derivability gate is the citation judge built in 260731-001 — it already asks
exactly "do these pages establish this ground-truth answer?".

| kind | inputs | accept iff |
|------|--------|-----------|
| `standard` | 1 corpus page | citation judge on that page alone = `fully` |
| `multi_source` | 2 pages, different files, same category | judge on both = `fully` **and** judge on each page alone ≠ `fully` (leave-one-out — this is what "spans two citations" means operationally) |
| `unanswerable` | category page inventory, 0 sources | judge over the BM25 top-k pages of the category = `not_at_all`, and a topicality check says a real customer of this category would plausibly ask it |

Every item additionally passes:

- **Form check** — first-person customer voice, self-contained, no reference to
  "the document/section/page", decisive ground truth.
- **Difficulty check** — an independent model classifies easy/medium/hard by
  the structural criteria above; must match the requested label.
- **Deterministic gates** — sources resolve through `evalharness.pages.PageStore`;
  Hebrew, non-empty; no (file, page) reused within a category×difficulty cell;
  not a near-duplicate (token Jaccard) of v1 or of an already-accepted item.

**Model assignment** — generator round-robins `google/gemma-3-27b-it`,
`zai-org/GLM-5.1`, `nvidia/Nemotron-3-Ultra-550b-a55b`; every verifier is a
*different* model than the item's generator, so no model grades its own work.
Recorded per item in `provenance`.

**Rejection handling** — up to 2 re-prompts with the rejection reason, then
resample the page (up to 3 pages), then record the item as failed and report
it. Nothing unverified is ever emitted.

## Coverage

- Candidate pages: ≥500 chars of extracted text; `hard`/`medium` prefer pages
  containing numbers (₪/%/digits).
- Within a category×difficulty cell every item uses a distinct (file, page),
  and the sampler prefers distinct *files*; the emitted coverage report lists
  distinct files/pages per category and flags any file used more than twice.

## Cost

~132 generations + ~400 verification calls + retries ≈ 600–800 calls, ~$1–2 on
the shared pool. Nemotron-Ultra is the slow/expensive member — it gets a third
of the generations, not the verifications.

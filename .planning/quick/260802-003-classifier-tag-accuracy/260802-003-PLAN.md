# Quick Task 260802-003 — classifier domain-tag accuracy

## Why

The 260801-004 analysis put domain-tag accuracy at **76-77% on v2** and
88-91% on v1, and named it the root cause of failure mode F1 (refusal
inflation): the agent filters retrieval to one wrong corpus slice, the
rerank gate finds nothing, the answer becomes a refusal. 260802-002 T1
already added the unfiltered-retry safety net (commit 642baee) — that
stops wrong tags from being fatal, but a wrong tag still wastes a
retrieval round and yields a worse pool than a right tag (or than no tag
at all). This task attacks the tag quality itself.

Engine semantics that define the metric (`rag/agent/engine.py:176`): a
sub-question filters retrieval **only when it carries exactly one
category**. Zero or ≥2 categories ⇒ no filter. So:

| prediction | effective filter | verdict |
|---|---|---|
| exactly `[gold]` | gold | **useful** |
| exactly one wrong tag | wrong | **harmful** |
| empty, or ≥2 tags | none | **safe but idle** |

Primary metric is therefore `harmful_rate` (lower is better), with
`filter_correct_rate` as the tie-break. A wrong filter costs far more
than a missing one.

## Ground truth

Both reference sets carry a single gold `domain` per question:
`reference_questions.json` (v1, n=48, 8 domains) and
`reference_questions_v2.json` (v2, n=121, all 12 domains, incl. 12
unanswerable + 8 multi_source). v2 is the harder, larger set and is the
selection set; v1 is the confirmation set. Every arm runs on both.

## Deliverables

1. `evalharness/classify_eval.py` — arm runner, metrics, paired stats, reports.
2. `evalharness/classify_prompts.py` — prompt-variant registry (eval-owned).
3. `evalharness/classify_arms.py` — arm definitions.

## T1 — Classification eval harness

Files: `evalharness/classify_eval.py`, `evalharness/classify_prompts.py`,
`evalharness/classify_arms.py`, `rag/classify.py` (two small hooks),
`tests/test_classify_eval.py`.

**Production hooks in `rag/classify.py`** (minimal, both used by the eval
and by the winner if it needs them):
- `QueryClassifier(..., system_prompt: str | None = None)` — override the
  built-in prompt. Default keeps today's behaviour.
- `classify(question, hint: str | None = None)` — when given, appended to
  the *user* message as a clearly-delimited evidence block. Remove this
  parameter at T5 if no hint arm wins (replace, don't deprecate).

**CLI**

```
python -m evalharness.classify_eval \
  --config configs/default.yaml \
  --questions reference_questions.json reference_questions_v2.json \
  --arms ARM [ARM ...] | --all \
  --out eval_results/classify-sweep-<TS> \
  [--concurrency 6] [--limit N] [--hints eval_results/.../hints.json] \
  [--build-hints] [--max-cost 5.0]
```

**Hints cache (`--build-hints`)** — one pass over all questions:
dense + sparse → RRF fuse, top 10, **no rerank** (the cross-encoder is the
expensive CPU stage and is not needed for a category prior). Record per
question: category histogram over the 10 hits, top-1 share, the 3
top-ranked hits' file + first 200 chars. Written to `hints.json` keyed by
question id, reused by every hint arm so the sweep is deterministic and
pays the retrieval cost once. Local qdrant holds a single-process lock —
build hints in its own pass, and keep retrieval concurrency ≤4.

**Per-question record** (`<arm>/predictions.jsonl`): `id, set, gold,
question, sub_questions[{question, categories}], categories,
effective_filter, verdict ∈ {useful, harmful, none}, recall_any,
parse_failed, finish_reason, latency_ms, cost_usd, raw_reply`.

**Per (arm, set) metrics** in `summary.json`: `n`, `harmful_rate`,
`filter_correct_rate`, `no_filter_rate`, `recall_any` (gold ∈ union of
tags), `mean_tags_per_sub`, `mean_sub_questions`, `parse_fail_rate`,
`truncation_rate` (finish_reason == "length"), `p50_ms`, `mean_cost_usd`,
plus pooled (v1+v2) rows. Paired against the `baseline` arm on the same
question ids: `n_fixed` (baseline harmful → arm not harmful), `n_broken`
(the reverse), and an exact **McNemar** p-value — n is small (169), so
every claim of improvement must survive this.

Also emit a confusion table (gold domain × predicted filter) so T3 can
see *which* domain pairs the classifier confuses.

**Cost/robustness:** bounded thread pool (`--concurrency`, default 6 — the
API key is shared), retry with backoff on 429/5xx, running cost total with
`--max-cost` abort, `report.md` with the arm × metric table.

**Tests** (`tests/test_classify_eval.py`, tf_client + retriever mocked, no
network): verdict classification for all three prediction shapes, metric
arithmetic on a hand-built fixture, McNemar counting, hint rendering,
self-consistency voting, `--limit`/`--max-cost` guards.

Run: `pytest tests/ -q` must stay green.

Commit: `feat(evalharness): classification arm sweep (metrics, hints, paired stats)`.

## T2 — Wide sweep

Build hints once, then run all arms on both sets into
`eval_results/classify-sweep-<TS>/`. Arms:

| id | what it changes |
|---|---|
| `baseline` | today's production prompt, gpt-oss-120b, reasoning low, temp 0 |
| `abstain` | + "a wrong tag is worse than none — if the domain is not clearly determined by the question, return an empty list" |
| `examples` | + 2 short example questions per category (hand-written from corpus vocabulary — **must not be drawn from either reference set**) |
| `rich-desc` | category descriptions extended with belongs / does-NOT-belong and explicit disambiguation of the overlapping families (health ↔ diseases-disabilities ↔ long-term-care, life ↔ mortgage, personal-accident ↔ loss-of-working-ability) |
| `decision-rules` | ordered decision rules: product/name cues first, then policyholder situation, then a stated precedence for overlaps |
| `hint-sparse` | baseline prompt + retrieval evidence block (category histogram + 3 snippets) |
| `hint-vote` | **no LLM** — filter = top hint category when its share ≥0.6, else none. Measures how much of the signal the index alone carries |
| `model-qwen` | baseline prompt on `Qwen/Qwen3-235B-A22B-Instruct-2507` |
| `model-deepseek` | baseline prompt on `deepseek-ai/DeepSeek-V4-Pro` |
| `effort-medium` | gpt-oss-120b, reasoning_effort medium |
| `selfcons-3` | baseline prompt, temp 0.7, 3 samples, keep categories with ≥2 votes (sub-questions from sample 1) |
| `verify-2stage` | baseline tags, then one cheap call that sees the retrieval evidence and may retract a tag |

Budget: ~2k calls, ~$2. Expect well under an hour; run under `nohup` and
poll rather than blocking a foreground call. Commit the results directory
and `report.md`.

Commit: `eval(classify): wide sweep — 12 arms on v1+v2`.

## T3 — Analysis

Read `summary.json` + the confusion tables. Produce, in
`260802-003-ANALYSIS.md`:
- arm ranking on pooled `harmful_rate`, with per-set breakdown and the
  paired fixed/broken counts vs baseline and McNemar p;
- which domain pairs dominate the residual errors, and whether they are
  genuinely ambiguous (question answerable from either domain's corpus) or
  a real classifier miss — sample the actual questions;
- whether the index hint carries independent signal (compare `hint-vote`
  errors with `baseline` errors — are they correlated?);
- selection rule, applied explicitly: **minimum pooled `harmful_rate`;
  among arms statistically tied with the best (McNemar p > 0.05), prefer
  higher `filter_correct_rate`; reject any arm that regresses harmful_rate
  by >3 points on either set individually.**

Note the overfitting caveat honestly: variants informed by the observed
confusions are fitted on the same 169 questions. Rules written into the
merged prompt must be general (domain-family disambiguation), never
question-specific.

## T4 — Merge and verify

Compose 2-3 merged arms from the components that won in isolation (e.g.
best prompt-content variant + abstain rule + best model + hint if it
carried signal), plus **leave-one-out ablations** of the merged winner so
each component's contribution is measured inside the merge, not only in
isolation. Run into `eval_results/classify-merge-<TS>/` on both sets.

The verification claim to settle: *merged > every isolated component*, on
pooled `harmful_rate`, with the paired test. If the merge does **not**
beat the best isolated arm, say so and ship the best isolated arm — that
is a legitimate outcome, not a failure to hide.

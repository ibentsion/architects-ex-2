# Quick Task 260801-004 — Agent-harness eval on the cloud

Run the new `--engine agent` harness on reference_questions.json (v1, 48q)
and reference_questions_v2.json (v2, 121q) on the Nebius L40S node, judge
every arm with the 3-model committee, download all artifacts, and analyze
failure modes.

## Decisions (confirmed with user)

1. **Both agent arms per dataset**: DeepSeek-V4-Pro synthesis (production
   candidate; `configs/embedder-bge-m3.yaml` — generation defaults to
   DeepSeek) AND gpt-oss-120b-low synthesis
   (`configs/final-per_table-bgem3-gptoss-low.yaml` — apples-to-apples with
   the existing v1 postrepair baseline). Orchestration is gpt-oss-low in
   both.
2. **v2 baselines**: classic `--engine rag` (gpt-oss-low config) AND a
   no-RAG bare-model arm via `baseline_runner.py` (DeepSeek-V4-Pro — the
   Stage-1 baseline convention; stated assumption).
3. Committee: gpt-oss-120b + Qwen3-235B-A22B-Instruct-2507 +
   DeepSeek-V4-Pro (postrepair panel; GLM excluded per project memory).
   v1 comparison arm: existing postrepair `after-repaired-index` results.

## Tasks

### T1 — Batch records carry agent diagnostics
`rag/cli/query.py`: batch mode adds `category`, `confidence`, and `trace`
(when present) to each record — required for loop/classification
failure-mode analysis. Unit test with a fake engine.

### T2 — cloud/agent_eval.sh
Six arms (v1-agent-deepseek, v1-agent-gptoss, v2-agent-deepseek,
v2-agent-gptoss, v2-rag-gptoss, v2-norag-deepseek), each generating answers
with stderr logs, then committee judging per arm; per-arm failure isolation
(`fail=1`, keep going); upload `eval_results/$RUN` (answers + logs + reports)
to the artifacts HF dataset. Smoke the agent on the node with one query
before the full job.

### T3 — Run, download, analyze
Push to GitHub, submit smoke job then full job (`--timeout 6h`), poll,
download results, and write a failure-mode analysis: verdicts by
difficulty/kind/category, abstention on unanswerable, citation accuracy,
loop/calc usage from traces, latency decomposition, agent-vs-rag-vs-norag
attribution; conclude with concrete improvement suggestions and what else
to test.

## What the numbers mean

1. **The harness itself is currently score-neutral-to-negative; the synthesis
   model is what moves quality.** Same synthesis model (gpt-oss-low):
   agent 5.69 vs rag 6.08 on v1, agent 4.26 vs rag 4.83 on v2. With DeepSeek
   synthesis the agent beats the v1 baseline (6.46 vs 6.08) and ties rag on
   v2 (4.80 vs 4.83). The classification/decomposition/pooling machinery
   works mechanically but doesn't yet buy accuracy on these datasets —
   which are dominated by single-topic questions (classifier says "single"
   for 95-98% of them).
2. **RAG value is unambiguous** (the point of the norag arm): bare DeepSeek
   hallucinates on 60% of v2 questions, cites nothing, and answers 11/12
   unanswerable questions confidently (abstention 0.08 vs 0.67 for every
   RAG arm). RAG halves hallucinations and makes abstention work.
3. **v2 is much harder than v1 for everyone** (best 4.83 vs 6.08) — new
   failure surface is shared by rag and agent, i.e. mostly retrieval/corpus,
   not harness.

## Failure modes (ranked by impact)

**F1 — Refusal inflation via empty gated pools (agent-specific, biggest).**
Agent arms refuse 40-41 answerable v2 questions (rag: 34); 13 (gptoss) /
11 (deepseek) are regressions on questions rag got right/partial. Of the
agent's answerable refusals, ~60% (24-25) had a **zero-chunk gated pool**,
and 12-13 involved a **wrong single-category filter** (classifier tagged a
sub-question with exactly one wrong category → retrieval filtered to the
wrong corpus slice → gate-fail → hard fallback). Overall gate-fails: agent
36 vs rag 30. Domain-tag accuracy is only 76-77% on v2 (88-91% on v1) —
v2 questions are phrased more ambiguously across domains.

**F2 — Sub-question rewriting can lose the original phrasing.** The agent
retrieves with the classifier's *rewritten* sub-questions, never the
original question. The v1 smoke showed this risk (rewritten sub-question
gated 0 while the topic was answerable); pooling does not include the
original phrasing's hits.

**F3 — Calculation questions fail on evidence, not arithmetic.** The
calculator itself was always right (10000-1500 etc.), but hard car/apartment
calc questions (v2-008/9/29/30) still judge incorrect with gated pools of
0-1 chunks: the numbers being retrieved/fed are wrong or missing. The
orchestrator also only sees 1500-char chunk heads — table tails with the
actual figures can be invisible to it.

**F4 — Shared unanswerable blind spots.** The same 3 questions fool every
RAG arm (v2-033-car-hard, v2-055-diseases-disabilities-medium,
v2-077-life-easy): plausible-sounding coverage that isn't in the corpus,
with enough near-miss evidence above the gate to generate from.

**F5 — Latency.** Agent adds ~0.4-0.6 s classification always; DeepSeek
synthesis p50 ≈ 4.8 s (vs 1.2 s gpt-oss); loop tail p95 ≈ 21 s. p50 totals:
rag 1.6 s < agent-gptoss 2.2 s < agent-deepseek 6.6 s.

## Recommended improvements (ordered)

1. **Never hard-fail a filtered retrieval**: when a category-filtered
   sub-question retrieval gates to zero, retry unfiltered (one policy line
   in the engine). Directly attacks F1's ~24 empty-pool refusals.
2. **Always include the original question in the prefetch pool** (it's
   concurrent — near-zero latency cost). Attacks F2, softens F1.
3. **Soften the category filter**: treat classifier tags as a boost/prior
   (e.g. retrieve unfiltered, prefer same-category at rerank margin), or
   only filter when the classifier tag matches the dense top-1's category.
4. **Difficulty-aware synthesis routing**: gpt-oss for single/easy,
   DeepSeek for multi/hard/calc — v1 shows DeepSeek is worth +0.4-0.8
   correctness; routing keeps p50 near 2 s for most traffic.
5. **Give the orchestrator full table chunks** (or raise the 1500-char cap
   for table-bearing chunks) so calculations use the right figures (F3).
6. **Classifier prompt**: add per-category example questions and an explicit
   "if unsure, tag nothing" instruction — 76% tag accuracy is the root of
   F1; empty tags are safe (no filter), wrong tags are not.

## What else should be tested

- **A/B the fixes**: unfiltered-fallback and original-question-prefetch are
  one-line changes; re-run v2-agent-gptoss and diff verdict transitions.
- **Gate-threshold sweep on v2** (0.25/0.30/0.35): even rag refuses 28% —
  some of that is calibration, not evidence absence.
- **Multi-source coverage**: only 8 multi_source questions exist (agent-ds 5.0
  vs rag 4.0 — promising but n is far too small to conclude the decomposition
  helps). Generate ~30 more multi-source/calc questions with refgen.
- **Classifier model swap** (Qwen3-235B vs gpt-oss as classifier) measured
  on domain-tag accuracy alone before rerunning full evals.
- **v2 retrieval audit independent of engines**: 30 gate-fails under rag
  mean the v2 gap is substantially retrieval; measure retrieval hit-rate
  against ground_truth_sources per question to separate corpus gaps from
  ranking failures.

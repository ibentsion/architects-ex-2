<objective>
Adapt the supplied enterprise RAG support-UI spec to this project and build it: a
React web app (`webui/`) plus a FastAPI bridge (`webapi/`) that streams the real
agentic RAG pipeline running on the Nebius GPU node, with a debugging/QA-history
view over the local answers/judgment JSONL files.

Purpose: Stage 3's optional bonus ("voice interface, simple UI"). The
differentiator over a generic chat UI is that this agent has a real trace —
classification tags, sub-questions, per-sub-question retrieval counts, tool
calls — and the UI shows it while it happens.

Output: `webapi/` (6 modules + 2 apps), `webui/` (Vite React TS app),
`cloud/serve_ui.sh`, one minimal event-sink hook in `rag/agent/engine.py`, and
bridge tests under `tests/`.
</objective>

<non_goals>
Restating the locked boundaries. Violating any of these is a plan failure, not a
judgement call:

- **`contract.py` is not modified.** It is the graded artifact. Every task's
  verify block includes `git diff --exit-code -- contract.py`.
- **No retrieval or generation quality changes.** No config edits, no prompt
  edits, no reranker/gate tuning. `configs/ship.yaml` is read, never written.
- **No auth.** No login, no sessions, no API keys in the UI.
- **No multi-turn memory.** The engine is stateless per query; the UI keeps a
  message list for display only and never sends history back.
- **No dual streaming/non-streaming code paths.** `webapi/agent_app.py` exposes
  one streaming endpoint. There is no `/ask` fallback in it and no
  "if streaming fails, POST the plain endpoint" branch anywhere in `webui/`.
- **No JS test framework.** Typecheck + build are the frontend gate.
- **`faster-whisper` is not added to `requirements.txt`.**
- **No new eval arms, no answer-file writes.** The QA-History view is read-only.
</non_goals>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> bridge | Untrusted query strings, dataset ids, citation `file`/`page` params, and audio blobs cross here. |
| bridge -> agent app | Bridge relays a question to a process that runs LLM calls and reads the index. |
| bridge -> filesystem | Every dataset and corpus read is driven by a request parameter. |
| agent app -> Token Factory | The shared key is used for classification/synthesis calls. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-260803-01 | Tampering | `GET /api/citation/*`, `GET /api/offline-pairs` `file`/`dataset` params | mitigate | Every path goes through `webapi/paths.resolve_in_repo`: absolute inputs rejected, `.resolve()` + `is_relative_to(REPO_ROOT)` catches `..` and escaping symlinks. Four traversal strings unit-tested (Task 2), two more at the route level (Task 5). |
| T-260803-02 | Information disclosure | bridge serving repo files | mitigate | Discovery is an allowlist of known globs, not an arbitrary browse API; `/api/offline-pairs` rejects any dataset id not in `discover_datasets()`. `.env`, `venv`, and `rag_index/` are unreachable by construction. |
| T-260803-03 | Denial of service | `POST /api/query` -> single shared engine | mitigate | The agent app serializes queries behind a lock (same reason `contract.py` does); a browser disconnect cannot fail an in-flight answer because the `_emit` sink swallows sink exceptions (Task 1). |
| T-260803-04 | Denial of service | thumbnail rendering | mitigate | Rendered once, then served from `cache/webui_thumbs/`; page number bounds-checked against the real page count before any render. |
| T-260803-05 | Spoofing | audio upload path | accept | Local-only tool on localhost with no auth by decision; no PII stored, nothing written to the repo. Documented in `webui/README.md`. |
| T-260803-06 | Information disclosure | Token Factory key | mitigate | The key never leaves the node process. The bridge holds no key and the frontend calls only same-origin `/api`. |
| T-260803-SC | Tampering | npm + pip installs | mitigate | pip adds only `httpx` and `python-multipart` — both already resolved transitively in `./venv`, no new upstream. npm packages are `vite`, `react`, `react-dom`, `typescript`, `tailwindcss`, `@tailwindcss/vite` — first-party, top-of-ecosystem.

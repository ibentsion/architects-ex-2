# Quick Task 260803-001: Customer-support web UI over the cloud agent - Context

**Gathered:** 2026-08-03
**Status:** Ready for planning

<domain>
## Task Boundary

Adapt the supplied "Enterprise RAG Customer Support Web UI" product spec to this
project and build it: a React web app that talks to the agentic RAG engine
(`rag/agent/engine.py`, `configs/ship.yaml`) running on the Nebius GPU node, plus
a debugging/QA-history view that can load the local answers/judgment JSONL files
produced by the eval runs.

This is the exercise's Stage 3 optional bonus ("voice interface, simple UI") —
not a graded artifact. `contract.py` is the graded artifact and must not change.

Out of scope: retrieval/generation quality changes, new eval arms, auth,
multi-turn session memory (the engine is stateless per query).
</domain>

<decisions>
## Implementation Decisions

### Cloud connectivity
- **Local bridge proxying `AGENT_BASE_URL`.** A FastAPI bridge runs on the
  laptop and forwards `/api/query` to the agent app, default
  `http://localhost:8000` — i.e. an SSH tunnel to the GPU node. The same bridge
  serves corpus-backed citation content and page thumbnails from the local
  `corpus/` tree, and the offline-pairs endpoints.
- Pointing `AGENT_BASE_URL` at a public node URL later must require no code
  change.

### Stack and layout
- **`webui/`** — Vite + React + TypeScript + Tailwind. **`webapi/`** — the
  FastAPI bridge (and the agent-side SSE app).
- `contract.py` is untouched: it is what the graders call.

### Agent-side streaming
- **New agent-side SSE app `webapi/agent_app.py`** that imports the same engine
  via `build_answer_engine(config, "agent")` and emits *real* pipeline events —
  retrieval hint, classification (domain tags, sub-questions, difficulty),
  each sub-question's retrieval result, agent-loop tool calls
  (retrieve/calculate), then the synthesized answer with citations.
  This app runs on the cloud node **instead of** `contract:app` for the demo.
- The engine's existing `trace` list already records exactly these steps — the
  hook should be an optional event-sink callback threaded alongside the
  existing `trace.append` calls, not a re-implementation of the pipeline.
- No fallback path that proxies a plain non-streaming `/ask`: one streaming
  contract, no dual mode.

### Voice input
- **Browser first, backend fallback.** Web Speech API (`he-IL`) where the
  browser supports it; otherwise MediaRecorder → multipart POST to the bridge.
- Token Factory has **no ASR** — verified 2026-08-03: 27 models, none audio;
  `/v1/audio/transcriptions` returns 404; `input_audio` content parts are
  rejected (422, content must be a string). So the backend leg cannot use the
  shared key.
- Backend STT is therefore a **pluggable transcriber, off by default**:
  `pip install faster-whisper` + an `STT_MODEL` env var turns it on (a Hebrew
  `ivrit-ai` model on the GPU node, `base` on CPU). Not added to
  `requirements.txt`. When it is absent the endpoint returns a clear
  "STT backend not configured" error that the UI surfaces — no silent failure,
  no fake transcript.

### Debugging / QA-history view
- **Server-side file picker over repo files.** The bridge scans the repo for
  answer JSONLs (`rag_answers_*.jsonl`, `team_1_results*.jsonl`,
  `baseline_answers.jsonl`), `eval_results/*/judgments.jsonl`, and
  `reference_questions*.json`, and exposes them as selectable datasets.
- Judged runs additionally surface the judge's grades/verdict and the reference
  answer next to each pair — that is the actual debugging use.
- File access must be confined to the repo root (no arbitrary path reads).

### Hebrew / RTL
- Corpus, questions and answers are Hebrew: the app is RTL by default with
  per-message direction detection so mixed Hebrew/English renders correctly.
  The supplied spec's LTR panel percentages are mirrored, not literal.

### Citations and thumbnails
- Citations are `{file, page}` into `corpus/<category>/files/*.pdf` and
  `corpus/<category>/pages/*.txt`. Thumbnails are rendered server-side from the
  PDF page with **pypdfium2** (already installed as a Docling dependency) and
  cached; `.txt` sources get a text-preview card instead of a page image.
- `content_preview` comes from the retrieved chunk text when the agent supplies
  it, else from the resolved corpus page.

### Claude's Discretion
- Component decomposition, state-management shape (Context vs store), exact
  palette within the "muted corporate slate/indigo" brief, animation timings,
  thumbnail cache location, test depth for the bridge endpoints.
</decisions>

<specifics>
## Specific Ideas

- The supplied spec's `/api/offline-pairs` schema (`id`, `question`, `answer`,
  `citations[{id, file_name, page_number, content_preview, thumbnail_url}]`) is
  the wire format for both views — the bridge adapts this project's `Answer` /
  `Citation` shapes onto it rather than the UI learning two schemas.
- Live view SSE event stream is richer than the spec's plain token stream
  because this agent has a real trace to show; the citation panel is populated
  from the final event.
- `cloud/submit_job.sh run 'bash cloud/...'` is how anything reaches the node;
  the demo needs a serve script analogous to `cloud/blind_run.sh`.
</specifics>
